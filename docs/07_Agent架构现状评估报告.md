# Agent架构现状评估报告

日期：2026-08-01    依据：AGENTS.md 第一性原理审查原则    方法：目录扫描 + 模块清点 + 记忆统计，未修改任何文件

## 一、事实基线

- CourseAgent 目录：agents 7个文件、core 10个文件、modules 10个文件、capabilities 4个文件、tools 8个文件、docs 7份、config 1份、memory 13+10个JSON。
- 记忆数据：compute_history 19条、improvements 8、success 8、rules 3+8、knowledge_updates 若干、user_preferences 有沉淀。
- 输出目录：存在临时工作文件（_work.docx、_core_work.docx、_skill_demo.docx、_batch_work.docx）与多份报告。

## 二、模块清点

| 层 | 现有实现 | 性质 |
|---|---|---|
| Agent | planner/writer/reviewer/learner/router/light_judge | 规则脚本 |
| Skill | skill.py、skill_factory（7个能力单元）、capabilities/ | 注册表+规则生成器 |

## 三、闭环完整性分析

任务闭环“输入→转译→规划→执行→检测→修复→打包→学习→更新”均有代码与运行记录，属于**可运行的工作流闭环**。

但按第一性原理拆解，以下环节是“规则模拟”而非“真实智能”：

1. 需求转译：关键词规则，无语义理解；
2. 记忆：JSON线性读写，无语义检索；
3. 任务状态：Orchestrator状态在内存，中断不可恢复；
4. 生成：模板/规则生成，无任何模型调用；
5. 知识：抓取候选，无“影响判断+确认”自动化；
6. 学习：写文件记录，无在线回流；
7. 视觉：程序化像素/文本检查，非视觉理解；
8. 评测：自评启发式，无可复现评测集。

## 四、当前定位

当前系统是“规则驱动的工作流框架（Workflow Agent）”，不是“自主推理Agent（Reasoning Agent）”。它能稳定执行已知流程、检测与沉淀，但尚不具备真正的语义理解、自主规划与在线学习。

## 五、距离真正 Agent 缺失的关键组件

1. LLM 适配层/模型路由（当前完全无模型调用）；
2. 语义需求转译（规则→模型）；
3. 语义记忆检索（JSON→向量/全文检索）；
4. 任务状态持久化与恢复；
5. 定时/守护运行机制；
6. 用户反馈在线学习闭环；
7. 可复现评测集与回归测试；
8. 视觉理解能力；
9. 知识候选“影响判断+确认”自动化；
10. 输出目录临时文件自动清理。

## 六、结论与建议

**结论**：架构骨架完整、流程可运行、质量底线有效，但核心决策与内容生成尚未接入模型层，距离“真正Agent”仍差“推理与学习引擎”这一层。

**建议路径**

1. 近期：接入LLM适配层与模型路由、任务状态持久化、建立评测集；
2. 中期：语义记忆检索、反馈在线回流、知识影响判断自动化；
3. 远期：在线学习、多智能体协作、视觉理解。

本报告仅作评估，未创建或修改任何文件。
