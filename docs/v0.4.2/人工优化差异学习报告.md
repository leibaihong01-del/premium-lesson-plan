# 人工优化差异学习报告（王欢黄金样本）

- 学习对象 A：原始生成版（Agent 生成并验收）
- 学习对象 B：人工修正后的最终 DOCX（黄金样本）
- 结论：以黄金样本为准，提炼通用文档质量规则；不将黄金版本判定为错误。

## 一、差异清单

| 维度 | 原始生成版 | 人工修正版（黄金） | 变化性质 |
|---|---|---|---|
| 表注编号 | `表2-1`（连字符） | `表2.1`（句点） | 编号格式修正 |
| 表注空格 | 编号与名称之间 1 个空格 | 2 个空格 | 空格规范修正 |
| 表注与表格 | 表注后跟表格 | 表注后紧跟表格（无空段落） | 绑定关系保持 |
| 表格列宽（表5） | 668/940/1437/2705/2145 | 857/1570/2185/2677/1995 | 表头优先重分配 |
| 表头单行 | `首选排查方向` 折行 | 单行显示 | 视觉修复 |
| 表格总宽 | 85%（固定） | 85%（自适应页面有效宽度） | 宽度策略 |
| 页数 | 22 | 23（列宽重排） | 非缺陷，记录 |
| 虚拟案例表述 | `长沙地铁网络` | `某城市轨道交通线路中的虚拟车站` | 内容真实性 |

## 二、人工为什么这样修改

1. 表注编号 `表X-X` 不符合学校模板的 `表X.X` 规则，且单空格不整齐；改为句点 + 两空格使编号与名称对齐、符合正式成果视觉。
2. 表头 `首选排查方向` 折行破坏首行语义，人工通过“表头优先”重分配列宽：序号列收紧，语义列放宽，保证单行。
3. 表注必须紧贴对应表格，中间不允许空段落，否则表格归属关系会被误读。
4. 虚拟车站不能绑定真实城市/线路，避免事实误解。

## 三、通用规则 vs 本案例特殊处理

### A. 必须固化规则（通用文档质量要求）

- 表注格式：`表X.X  表名称`，编号与名称之间两个空格；
- 表注必须紧贴对应表格（表注→表格首行→表格内容为一个视觉单元）；
- 表头 3~6 个汉字优先单行；换行时先调列宽（gridCol 与 tcW 同步），再调表格宽度，最后调单元格空间；
- 表格宽度按页面有效宽度自适应，页面利用率与内容可读性优先；
- 表格之间允许视觉分隔，但表注不得与其表格分离。

### B. 特定模板规则（学校模板相关）

- 表注编号格式 `X.X`（本学校模板）；
- TOC 右对齐制表位 9355、点引导线；
- 页边距与版心宽度。

### C. 个人审美/案例特殊处理（不进入通用规则）

- 表 5 各列的具体分配比例；
- 页数由 22 变 23 的重排结果；
- 虚拟案例的具体措辞（案例名保留策略）。

## 四、表注编号差异来源确认

- 旧版 DOCX：`表2-1 AFC检票机系统组成表`（连字符 + 单空格），属于原始生成缺陷；
- 新版 DOCX（黄金）：`表2.1  AFC检票机系统组成表`（句点 + 双空格），人工已修正，正确；
- PDF 文本层将 ASCII 句点显示为 `-`：属 Word/Times New Roman 对 ASCII `.` 的渲染行为，不是黄金 DOCX 的缺陷；
- 规则要求：表注编号所在 run 应使用中文字体（eastAsia 提示），避免渲染层字形变化。

## 五、沉淀建议

- 将“表注编号句点 + 双空格 + 与表格绑定”加入 document_quality_gate_rules；
- 将“表头单行优先 + 列宽自适应”加入 Table Quality Gate；
- 建立 DOCX 结构检查 + PDF 视觉检查双通道验收。
