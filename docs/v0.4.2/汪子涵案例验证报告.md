# 汪子涵案例验证报告

- 学生：汪子涵
- 方向：屏蔽门系统
- 案例站点：丁字湾站
- 课题：丁字湾站屏蔽门常见故障排查方案设计
- 结论：通过质量门禁，达到交付标准

## 一、验证结果

| 门禁 | 结果 |
|---|---|
| 内容门禁 | 任务书题目一致、结构覆盖、逻辑闭环通过；专业词密度 17.43/千字通过 |
| 模板门禁 | Word Quality Gate 50/50 通过 |
| 视觉门禁 | PDF 19 页、无空白/溢出；表头单行；表注绑定 |
| 文本规范 | 中文标点字体异常 0；禁用表达 0；虚拟案例表述正确 |
| 交付门禁 | TOC 域存在、页码右边界统一 538.7、updateFields=true |

## 二、A. 当前规则成功避免的问题

1. 模板骨架保留（4 分节、6 表、目录域、页码域）；
2. 正文样式绑定与中英文 Run 分离；
3. 参考文献自动编号恢复；
4. 虚拟案例真实性检查发现并修复“长沙地铁网络”绑定；
5. 屏蔽门专业词库接入后专业词密度达标。

## 三、B. 新发现问题（含来源/检测/修复）

| 问题 | 来源 | 检测方法 | 修复方式 | 是否通用 |
|---|---|---|---|---|
| 核心专业术语“故障诊断”缺失 | 内容质量引擎词库过严 | CORE_TERMS 覆盖检查 | 记录为词库调整建议（正文已含“故障排查/原因分析”） | 是（建议同义词判定） |
| 表注仍为“表2-1”+单空格 | 学生初稿表注格式 | 表注格式检查 | 自动规范为“表2.1”+两空格 | 是 |
| 1 处“本文”残留 | 初稿表达 | 禁用表达扫描 | 替换为“本设计” | 是 |
| TOC1 段落制表位缺失 | Word 更新后样式/段落制表位被重置 | PDF 页码右边界检测 | XML 级注入 9355 制表位 | 是 |

## 四、C. 建议沉淀规则

1. 表注格式规则升级为“生成阶段强制规范化”，不再依赖学生初稿；
2. 核心专业术语检查支持同义词（故障诊断/故障排查/原因分析）；
3. Word 更新后必须复检 TOC 制表位与 updateFields；
4. 虚拟案例真实性检查应作为内容门禁固定项。

## 五、与王欢案例差异

- 王欢：表注初稿已是“表X.X”（仅验证）；汪子涵：初稿为“表X-X”，需规范化 → 证明表注规则必须前移到生成阶段。
- 王欢：无“本文”残留；汪子涵：1 处 → 禁用表达扫描为通用必需。
- 两案例均需后处理（标点字体、表格列宽、TOC 制表位、updateFields），说明应固化为最终排版收敛步骤。
