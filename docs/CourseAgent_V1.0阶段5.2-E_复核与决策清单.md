## 一、决策对象

是否将“DeepSeek增强Translator”从试点扩大为默认路径（或保留规则路径）。

## 二、决策前置原则

1. 扩大接入是重大变更，必须人工决策；
2. 当前会话内评测存在同模型偏差，不能作为唯一依据；
3. 不达标、不确定则不扩大，保持规则路径。

## 三、独立/人工复核清单

### 1. 结果复核

- [ ] 人工审阅 evaluation/reports/translator_deepseek_incontext_v1.0.md；
- [ ] 抽查10个TaskSpec，判断是否符合Prompt契约与真实需求；
- [ ] 确认“会话内生成”与“规则基线”的差异是否合理。

### 2. 独立验证（可选，推荐）

- [ ] 用独立模型/API对同一10案例复测；
- [ ] 或由人工对10案例逐一判定正确性；
- [ ] 对比指标：内容质量、结构完整、任务符合度。

### 3. 成本与延迟

- [ ] 设定并记录单次token上限（建议512）；
- [ ] 设定试点调用总量上限（建议≤50次）；
- [ ] 实测响应时间与成本并记录。

### 4. 架构与回退

- [ ] 确认LLM仅经 Model Adapter + Router 调用；
- [ ] 确认关闭开关后自动回退规则路径；
- [ ] 确认回归测试（现有测试集）通过。

## 四、决策标准

满足以下条件才考虑扩大：

1. 独立/人工复核通过；
2. DeepSeek或Hybrid优于规则基线；
3. 成本与延迟在预算内；
4. 回滚验证通过。

不满足任一条件：不扩大，维持规则路径。

## 五、决策选项

- 选项A：扩大为Hybrid（规则优先，失败转LLM）；
- 选项B：扩大为LLM默认+规则校验；
- 选项C：不扩大，保持规则路径（推荐当前选择，直到独立复核完成）。

## 六、结论

当前建议选择“选项C：不扩大”，先完成独立/人工复核后再重新决策。本清单输出前未执行任何扩大接入。
