# 毕业设计生成经验系统设计

版本：0.5-draft
状态：设计稿，未编码

## 一、目标

让 CourseAgent 从多个案例中总结最佳生成路径，自动选择更优方案，而不是每次遇到问题增加规则。

## 二、案例结构

```
case_record:
  case_id
  student
  direction
  document_type
  result: 通过/失败/部分通过
  problems:
    - problem_id
      problem
      cause_layer
      cause
      solution
      effect_score
  artifacts:
    - generation_plan
    - template_schema
    - diff_report
    - quality_report
  validation_status: gold/validation/candidate
```

### 问题层分类

- content_model：内容模型问题（如结构缺失、语义分类错误）
- template_space_constraint：模板空间约束问题（如超页、区域容量不足）
- word_structure：Word 结构问题（如样式、域、分节）
- generation_strategy：生成策略问题（如搬运式生成、全量重建）
- reviewer_capacity：验收能力问题（如检查项缺失）

## 三、经验抽取方式

### 禁止

- 把单案例特殊修改直接沉淀为规则；
- 记录“删除空段落规则”这类操作层结论；
- 未经验证写入长期 Memory。

### 必须

1. 先做差异分析；
2. 识别问题所属问题层；
3. 抽象根因；
4. 形成可复用的解决策略；
5. 经下一次生成或历史案例验证；
6. 通过后升级为正式规则。

### 抽象示例

- 邱志豪超页：不是“删除空段落”，而是“固定页模板生成前必须做区域容量预测”；
- 表头折行：不是“某列加宽”，而是“表头短标题优先单行，列宽优先于字号/边距调整”；
- 引号字体：不是“某个 run 改宋体”，而是“中文标点必须校验 Unicode+字体+PDF 渲染”。

## 四、策略评分机制

策略对象：

```
strategy:
  id
  name
  success_count
  fail_count
  sample_size
  effect_score
  confidence
  last_used_at
```

评分公式（设计建议）：

```
success_rate = success_count / sample_size
confidence = 1 - 1 / max(sample_size, 1)
score = success_rate * confidence
```

选择规则：

- sample_size >= 3 时，选择 score 最高的策略；
- sample_size < 3 时，使用默认保守策略（规划后生成）；
- 每次案例验证后更新计数与评分；
- 质量下降时回退并记录回退原因。

## 五、Skill 升级机制

```
人工修订/案例结果
    ↓
差异分析
    ↓
问题层归类
    ↓
候选策略
    ↓
下一次生成验证
    ↓
通过 → 升级为正式规则
失败 → 回退或调整
```

升级边界：

- 不直接修改现有 Skill 正文；
- 正式规则进入 `rules/` 并标注 rule_id、来源、验证状态；
- 案例证据保留在 `memory/` 或 `experience/`；
- 每次升级记录版本、来源、影响范围。

## 六、与现有经验层关系

- 现有 `experience/candidates` 升级为候选策略池；
- 现有 `memory/golden_cases` 保留黄金案例证据；
- 现有 `memory/validation_cases` 保留验证案例证据；
- 新增 `strategy_scores.json` 保存策略评分；
- 新增 `problem_layers.yaml` 保存问题层定义。

## 七、验收标准

- 新案例能够被问题层归类；
- 每个候选策略有样本量与评分；
- 策略选择可解释（为什么选 A 不选 B）；
- Skill 升级有版本、来源、验证状态；
- 无未经验证的经验直接进入长期 Memory。
