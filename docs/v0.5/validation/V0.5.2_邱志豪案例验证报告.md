# V0.5.2 邱志豪案例验证报告

- 验证方式：仅生成验证产物，不修改 V0.4/V0.3 代码，不接入生产，不升级 Skill，不自动修改经验库
- 验证对象：邱志豪任务书（太平街口站电梯常见故障分析与检修方案设计）
- 产物目录：`docs/v0.5/validation/`

## 一、旧流程问题

旧流程为“直接生成 → 检查 → 修复”：

1. 首次生成未考虑区域容量与页面规划；
2. 首次渲染为 3 页，模板约束为 2 页，内部审核 `pages_ok=false`；
3. 问题层级：`template_space_constraint`（模板空间约束）；
4. 修复方式：移除设计目标/设计任务单元格尾部空段落 6 个，页数收敛为 2；
5. 旧流程的问题不是“少了一条删除空段落规则”，而是生成前没有容量预测。

## 二、新流程预测

根据实际模板容量数据：

- 设计目标：黄金模板 245 字符 / 6 个非空段落 / 行高 3670 twips；
- 设计任务：黄金模板 199 字符 / 7 个非空段落 / 行高 5102 twips；
- 预期成果：224 字符 / 11 个非空段落，固定内容无缩减余量；
- 总页数约束：2 页。

Planner 对邱志豪案例应提前输出：

```
page_overflow_risk: high
risk_reason:
- 课题名20字超过黄金模板18字，换行风险增加
- 设计任务接近容量上限
- 内容区尾部空段落占用第2页空间
- 预期成果无缩减余量
```

即：超页风险可以在生成前被预测，而不是生成后才发现。

## 三、改进价值

如果启用 V0.5.2：

1. 生成前即可识别“设计任务接近容量上限”；
2. 可在生成阶段直接控制内容区空段落数量，避免首轮 3 页；
3. 可输出页面布局预测，指导内容分配；
4. 预期成果与签字区可提前标记为固定页保护区域；
5. 旧流程的“首次失败+后修复”有机会变为“首轮接近达标”。

## 四、结论

### 1. Template Knowledge Model 是否有效？

有效。基于真实模板可表达结构（18x14 表格与区域）、空间（页数/行高/字符/段落容量）、语义角色（goal_statement/task_decomposition 等）与不变式（总页数 2、固定区域不可破坏）。

### 2. Generation Planner 是否能提前发现问题？

能。通过容量对比可预测邱志豪案例的高超页风险；但仍需后续真实回测（启用 Planner 后重新生成）验证预测命中率。

### 3. 是否值得进入下一阶段编码？

值得进入“Template Knowledge Model + 轻量 Planner”的原型编码；Strategy Selector、A/B 评估继续暂缓。

### 4. Schema 需要调整哪些内容？

1. 增加 `blank_paragraph_slack`：空段落容量是本次超页的关键变量；
2. 增加 `height_rule`：`atLeast/exact` 决定容量是软约束还是硬约束；
3. 增加 `text_wrap_estimate`：仅按字符数不足以预测换行，需考虑列宽与字符宽度；
4. 增加 `row_range/page_expected`：帮助 Planner 做页面布局预测；
5. 增加 `source_evidence`：容量数据应记录来自哪个模板/版本，便于追溯。
