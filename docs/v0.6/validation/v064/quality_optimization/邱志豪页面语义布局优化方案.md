# 邱志豪任务书页面语义布局优化方案

- 目标：达到黄金案例的页面语义布局质量，不是只解决页数
- 当前状态：页数/表格/目标+任务同页/成果+进程+签字同页 通过；设计进程整体性未达标
- 边界：不修改代码，不固化经验，仅形成候选

## 一、为什么设计进程跨页

1. 第1页内容被设计目标、设计任务占满，设计进程从第1页底部开始；
2. 课题长度与换行估算未纳入页面规划，实际行高超出预期；
3. 生成规划只控制区域容量，没有控制“区域所属页面”和“禁止拆分区域”。

## 二、当前生成规划缺少什么约束

缺少：

- `no_split_region`：设计进程不得拆分；
- `region_start_page`：设计进程应起始于第2页；
- `page1_end_boundary`：第1页内容应在设计任务结束；
- 页面语义布局不变量检查。

## 三、内容空间分配调整策略

1. 第1页只容纳：基本信息 + 设计目标 + 设计任务；
2. 设计目标控制在 230-260 字符 / 6 段；
3. 设计任务控制在 190-220 字符 / 7 段；
4. 空段预算按 0/0 优先，避免挤占页面；
5. 使用 text_wrap_estimate 预留课题长度导致的换行余量；
6. 若第1页容量仍不足，先压缩目标/任务内容，不允许设计进程提前到第1页；
7. 若在 2 页约束下仍无法保持设计进程完整，输出 deviation 并人工确认，不静默通过。

## 四、是否需要增加 no_split_region 约束

需要。建议加入：

- TKM：`page_layout.no_split_regions=["设计进程"]`；
- Generation Plan：`page_plan` 明确 `page2=["设计进程","预期成果","签字审核区"]`；
- Reviewer：检查设计进程是否跨页，跨页则输出 deviation。

## 五、验收标准

- 设计进程整体位于第2页；
- 第1页只含基本信息+目标+任务；
- 预期成果+设计进程+签字区域同页；
- 总页数 2；
- 无 violation；若语义单元拆分则 deviation，不判优秀。

## 六、结论

本轮优化不是“修页数”，而是把“页面语义单元完整性”纳入生成规划与验收。
