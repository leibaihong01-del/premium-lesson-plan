# 教师反馈闭环机制审查报告

日期：2026-08-03
性质：只读架构审查，未修改代码

## 一、结论

CourseAgent 已具备教师反馈闭环的“流程定义”和“规则/经验载体”，但**底层机制尚未完整闭环**，当前判定为：

B 只有任务级流程，没有完整底层机制

## 二、逐项检查

### 1. 是否存在流程定义：是（部分）

- result/review_loop.md：AI生成版 → 人工修改 → 差异提取 → 规则判断 → 经验升级
- result/workflow.md：第 10 步人工批阅 → 差异分析 → 规则沉淀
- result/rules/dual_version_rules.md：双版本交付与元数据

### 2. 是否存在反馈数据结构：部分

- version.json 元数据（origin / review_status）已定义；
- review_loop.md 定义差异字段（位置/类型/原因/通用性）；
- 缺少结构化“反馈案例 JSON”实际存储（AI vs 人工差异未入库）。

### 3. 是否存在经验库存储位置：是（分散）

- expert_rules/content_rules.json：教师经验规则；
- result/content_check 为执行层，未挂接经验目录；
- content_compliance/experience/README.md 为遗留目录；
- 工作区 00_系统配置/经验库 仍存放部分经验。

### 4. 是否存在规则被生成流程调用的路径：部分

- 质量检测：content_check/validator.py 读取 school_rules + expert_rules，调用路径存在；
- 生成流程：result_reference_builder.py 的中和规则为硬编码，未动态读取 expert_rules，生成侧缺少规则调用路径。

### 5. 王欢案例归属：B

- 已完成任务级双版本、差异分析报告；
- 但差异未结构化沉淀为反馈案例，规则未由生成流程动态调用。

## 三、最小补充方案（不修改代码，仅规划）

1. 生成流程改为读取 expert_rules/content_rules.json 执行中和与合规，移除硬编码规则；
2. 新增 graduation_design/review/feedback_cases/，人工批阅后生成 feedback_case_<id>.json；
3. 统一教师经验入口为 expert_rules，废弃/迁移 content_compliance 遗留目录；
4. 新增 result/content_check/experience/README.md，指向 expert_rules 与 feedback_cases。
