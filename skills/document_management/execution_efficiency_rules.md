# 执行效率优化原则（Execution Efficiency）

版本：1.0

## 一、核心目标

在保证质量、可靠性与可维护性的前提下，根据任务复杂程度动态选择最优执行路径。

简单问题简单处理；复杂问题深入处理；不要为了复杂而复杂，也不要为了节省资源降低必要质量。

## 二、任务复杂度判断

1. 输入复杂度：单文件/多文件、结构复杂度、多来源资料。
2. 输出复杂度：简单文本、固定模板填充、复杂排版、多文件协同。
3. 风险程度：是否正式提交、格式准确性要求、不可逆风险。

## 三、动态执行模式

| 模式 | 适用 | 流程 |
|---|---|---|
| 简单模式 | 简单修改、单文件转换、明确模板填充 | 理解需求 → 执行 → 基础检查 → 输出 |
| 标准模式 | 正式文档生成、模板转换、教学材料 | 需求分析 → 模板解析 → 生成 → 基础质量检查 → 输出 |
| 深度模式 | 新模板首次学习、复杂项目、批量校准、高风险材料 | 模板分析 → 规则提取 → 案例生成 → 质量检测 → 问题修正 → 经验沉淀 |

## 四、避免无效消耗

默认禁止：无必要重复测试、无价值报告、无必要格式转换、无必要图片分析、已验证问题重复验证。

每个额外步骤必须回答：是否提升最终质量？不能提升则不执行。

## 五、文档生成优先目标

模板理解、内容正确、格式保持、文件可用。

不优先追求：复杂评分体系、大量过程报告、过度自动化。

## 六、阶段性策略

先验证核心能力；再沉淀规则；再扩大规模；最后提高自动化。

首次新类型文件允许深度分析；已成熟文件走快速路径。
