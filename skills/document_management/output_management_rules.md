# 毕业设计成果输出管理规范

版本：1.0
状态：规则稿
适用范围：所有毕业设计材料生成、归档、交付

## 一、核心原则

1. 输出不是单个 Word 文件，而是一套可交付、可归档、可管理的毕业设计成果包；
2. 不同学生成果必须隔离，禁止混放；
3. 文件命名继承杨振海黄金案例命名规则；
4. 命名与目录整理属于生成流程，不是交付后处理；
5. 禁止模型自行决定文件名；
6. 专业方向不写死，通过 StudentProjectRegistry 扩展。

## 二、学生成果目录规则

每个学生生成成果时自动创建独立目录：

```text
06_输出成果/
 └── 专业方向/
      └── 学生姓名_毕业设计材料/
           ├── 01 学生姓名 毕业设计任务书 毕业设计题目.docx
           ├── 02 学生姓名 毕业设计成果 毕业设计题目.docx
           ├── 03 学生姓名 毕业设计成绩评定表 毕业设计题目.docx
           ├── 04 学生姓名 毕业设计答辩记录表 毕业设计题目.docx
           ├── 05 学生姓名 毕业设计指导记录表 毕业设计题目.docx
           ├── 其他材料/
           └── _过程记录/
```

规则：

- 正式成果文件按编号直接放在学生成果目录；
- 过程文件（AI生成版、人工修订版、验证报告）放入 `_过程记录/`；
- 未归类辅助材料放入 `其他材料/`；
- 专业方向目录名与 StudentProjectRegistry 中的方向一致；
- 不同学生禁止共用目录。

## 三、文件命名规则

格式：

```text
编号 + 空格 + 学生姓名 + 空格 + 文档名称 + 空格 + 毕业设计题目 + .docx
```

示例（杨振海黄金案例命名）：

```text
01 杨振海 毕业设计任务书 黄兴南路站AFC闸机设备检修方案设计.docx
02 杨振海 毕业设计成果 黄兴南路站AFC闸机设备检修方案设计.docx
03 杨振海 毕业设计成绩评定表 黄兴南路站AFC闸机设备检修方案设计.docx
04 杨振海 毕业设计答辩记录表 黄兴南路站AFC闸机设备检修方案设计.docx
```

## 四、编号规则

编号代表成果类型，禁止按生成顺序随机编号：

| 编号 | 文档类型 |
|---|---|
| 01 | 毕业设计任务书 |
| 02 | 毕业设计成果 |
| 03 | 毕业设计成绩评定表 |
| 04 | 毕业设计答辩记录表 |
| 05 | 毕业设计指导记录表 |
| 06 | 开题报告 |
| 07 | 中期检查表 |

新增材料类型必须先在规则中扩展编号，不允许临时编号。

## 五、Output Naming Sense

检查项：

1. 文件名是否符合规范；
2. 学生姓名是否一致；
3. 毕业设计题目是否一致；
4. 编号是否正确；
5. 目录结构是否正确；
6. 不同学生是否隔离。

输出：`output_validation_report.json`

状态：pass / fail / unknown

任一检查不通过，文件不得进入最终交付目录。

## 六、StudentProjectRegistry

用统一注册表管理学生与课题，禁止写死专业方向数量：

```text
专业
 ↓
专业方向
 ↓
班级
 ↓
学生
 ↓
课题
 ↓
生成材料集合
```

注册表为生成目录、文件命名、材料清单的唯一事实来源。

Schema：`student_project_registry_schema.json`

## 七、输出流程

```text
内容生成
 ↓
质量检查
 ↓
命名检查（Output Naming Sense）
 ↓
目录整理
 ↓
最终交付
```

模型不得自行决定文件名或目录位置。

## 八、边界

- 不修改 V0.4/V0.6 生产链路；
- 新增能力默认关闭；
- 不自动固化经验；
- 不删除历史验证案例。
