# 自主执行与单步验证闭环机制（Autonomous Execution Loop）

版本：1.0
位置：CourseAgent 底层运行纪律，适用于所有工作流（毕业设计、课程建设、教案、项目申报、Word 文档处理、模板生成）。

## 一、核心原则

Step-by-step Autonomous Loop：执行一步 → 检测一步 → 分析一步 → 确认一步 → 记录一步 → 进入下一步。

禁止：

- 执行多个步骤后再统一检查；
- 未验证结果直接进入下一阶段；
- 每一步都询问用户是否继续；
- 让用户承担流程控制工作。

用户角色：提供目标、提供反馈、最终验收。用户不是操作员、流程控制器或测试人员。

## 二、单步骤执行协议

每个 Action 执行后自动触发 Validation：

1. 执行当前动作；
2. 自动检测结果（按任务类型选择：文档任务检查文件生成/命名/结构/格式/异常；代码任务检查测试/影响/新错误；数据任务检查完整性/一致性/质量）；
3. 结果判断：
   - 正常 → 继续下一步；
   - 存在偏差 → 暂停内部流程，分析原因；
   - 严重异常 → 停止任务，请求人工判断。

## 三、问题分析原则

发现问题后禁止立即修改代码，先输出内部分析：

问题 / 现象 / 影响 / 根本原因 / 所属层级：

- A 输入理解问题
- B 模板解析问题
- C 内容理解问题
- D 生成逻辑问题
- E 格式控制问题
- F 校验缺失问题
- G 程序实现问题

然后选择最小修改方案。

## 四、最小修改原则

发现问题 → 定位原因 → 最小范围修改 → 重新执行检测 → 确认有效 → 沉淀经验。

禁止为修复一个案例而大范围重构、覆盖已有规则、删除检测机制、修改无关模块。

## 五、经验消化

任务结束后必须执行 Experience Digest：案例 → 问题记录 → 原因分析 → 解决方式 → 候选规则 → 验证 → 进入经验库。

单个案例不能直接成为全局规则，必须经过验证。

## 六、阶段性交付规范

连续执行任务，仅在以下情况暂停：

1. 需要人工专业判断；
2. 阶段任务完成；
3. 输出最终验收版本。

暂停时必须提供：完成文件、文件路径、可打开查看入口、自动检测报告、差异分析报告、经验沉淀结果。

不要输出大量中间操作日志、无意义步骤确认、要求用户点击继续。
