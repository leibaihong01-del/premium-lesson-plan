# 文档修改真实性验证规则

版本：1.0
适用范围：所有 Word/DOCX、PDF、Office 文档修改任务。

## 一、总原则

禁止仅根据执行过程或预期结果声明修改完成。

必须走“修改前取证 → 实际写入 → 修改后取证 → 真实差异判定”闭环。

## 二、真实修改闭环

### Step 1：修改前取证

- 保存当前文件状态；
- 提取目标区域 XML/结构快照；
- 记录关键属性。

### Step 2：执行修改

- 必须对实际文件进行写入；
- 必须生成新的输出文件。

### Step 3：修改后取证

- 重新打开保存后的文件；
- 再次提取对应 XML/结构；
- 与修改前快照进行真实差异比较。

### Step 4：结果判定

只有同时满足以下条件，才允许输出“修改完成”：

- A. 检测到实际文件差异；
- B. 差异位于用户指定范围；
- C. 修改后的属性符合模板要求；
- D. 重新加载文件后修改仍然存在。

## 三、禁止行为

- 根据代码执行成功判断修改成功；
- 根据日志判断修改成功；
- 根据预期参数判断修改成功；
- 编造差异报告；
- 仅输出理论参数即宣称完成。

## 四、未完成判定

出现以下任一情况，必须输出：

“未检测到实际修改，任务未完成。”

- XML 无变化；
- 文件未变化；
- 修改无法验证；
- 只生成了理论参数。

## 五、报告必须包含

1. 修改前实际值；
2. 修改后实际值；
3. XML 差异位置；
4. 文件验证结果。
