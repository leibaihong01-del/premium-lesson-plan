# 样板文件管理规则 V1.0

## 一、样板文件定义

教案样板不是最终冻结文件，其作用：验证模板结构、验证生成流程、提供格式基准、作为后续批量生成参考。样板允许进行身份信息修正、通用信息更新、错误残留修复。

## 二、样板三重属性

1. 模板基准属性：页面结构、表格结构、行列数量、合并方式、字体体系、颜色体系、页眉页脚结构。禁止修改。
2. 课程实例属性：课程名称、课程编码、专业名称、学时、学分、授课章节、项目名称。必须保持正确。
3. 质量验证属性：作为批量生成前基准，需通过模板一致性、内容一致性、视觉检查。

发现模板残留信息（原课程名称、原课程编码、原专业、原章节）属于“模板污染”，必须自动修正。

## 三、样板修改权限分类

- A类 必须自动修正：课程名称、专业名称、课程编码、学时、章节名称、页眉页脚课程名称等课程身份信息。
- B类 需要人工确认：教学目标、教学过程、思政内容、教学案例等教学设计调整。
- C类 禁止修改：表格结构、行列数量、合并方式、页面布局、字体体系。

## 四、样板生成后的自动检查

生成样板后必须执行身份检查：课程名称、课程编码、专业、学时、章节。发现模板遗留信息→自动修正→记录经验。

## 五、批量生成前最终检查

模板检查 → 样板身份检查 → 课程标准一致性检查 → 教学计划一致性检查 → 批量生成。

## 六、经验沉淀

E-009：样板身份一致性检查机制。模板复用导致原课程信息残留，原因在于模板结构信息与课程实例信息混淆，解决方案为增加样板身份审核节点。适用所有课程资源生成项目。
